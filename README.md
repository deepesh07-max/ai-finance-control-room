## 🎯 What This Does

Finance teams manually cross-check bank statements against payment gateway settlement reports every day — a slow, error-prone process. **AI Finance Control Room** automates this:

1. Ingests two data sources — **bank statements** and **Razorpay settlement records**
2. Matches each Razorpay payout to its corresponding bank entry
3. Flags **discrepancies** (amount mismatches) and **unhandled exceptions** (missing bank records)
4. Surfaces a live reconciliation dashboard with an **AI diagnosis** for every flagged record
5. Lets the user ask free-form finance questions to an AI agent (via Gemini)

The result: a "control room" view of settlement health — reconciliation rate, net variance, and exactly which transactions need human attention, with an AI-generated explanation for each one.

---
```

- **Frontend**: Next.js 16 (App Router) + React 19 + Tailwind CSS 4, deployed as a client-side dashboard
- **Backend**: FastAPI (Python), deployed on Render, doing the actual reconciliation logic
- **AI layer**: Google Gemini (`gemini-3.6-flash`) answers free-text finance questions
- **Data**: Synthetic JSON datasets (55 records) generated by `seed_data.py`, with deliberate edge cases baked in for demo purposes

## ⚙️ How Reconciliation Works

For each Razorpay settlement record, the backend (`main.py`) looks up the matching bank record by reference number and classifies it into one of three buckets:

| Status | Meaning |
|---|---|
| ✅ **MATCHED** | Bank amount equals Razorpay net payout (fees + GST fully accounted for) |
| ⚠️ **DISCREPANCY** | A bank record exists but the amount doesn't match — variance is calculated and flagged |
| ❌ **UNHANDLED_EXCEPTION** | No corresponding bank record found at all — settlement exists in Razorpay but never hit the bank |

The API then returns:
- **Metrics**: total records, matched count, unhandled/discrepancy count, reconciliation rate %, net variance
- **Audit logs**: a line-by-line breakdown per transaction, each with a plain-English AI diagnosis

### Seeded Edge Cases (for demo purposes)
`seed_data.py` generates 55 synthetic transactions and deliberately injects:
- **Record #15** — a fee mismatch (forces a DISCREPANCY)
- **Record #30** — missing entirely from bank statements (forces an UNHANDLED_EXCEPTION)
- **Record #45** — a delayed bank posting date (timing mismatch scenario)

This makes the dashboard demo-able out of the box without needing real bank/payment data.

## 🔌 API Reference

### `GET /`
Health check — confirms the engine is online.

### `GET /api/reconcile`
Runs the full reconciliation pass across both datasets and returns metrics + audit logs.

**Response shape:**
```json
{
  "metrics": {
    "total_records": 55,
    "matched_count": 52,
    "unhandled_count": 3,
    "reconciliation_rate": "94.5%",
    "net_variance": "$-150.00"
  },
  "audit_logs": [
    {
      "tx_id": "pay_RZP_1001",
      "bank_ref": "BANK_REF_5001",
      "bank_amount": "$1396.06",
      "razorpay_payout": "$1396.06",
      "status": "MATCHED",
      "variance": "$0.00",
      "ai_diagnosis": "100% net match across fees ($28.60) & GST ($5.15)."
    }
  ]
}
```

### `POST /api/ai-query`
Sends a free-text finance question to the Gemini-powered AI controller.

**Request:**
```json
{ "query": "Why might a settlement show a variance?" }
```

**Response:**
```json
{ "response": "..." }
```

> Requires a `GEMINI_API_KEY` environment variable to be set on the server. Without it, the endpoint returns a clear configuration error instead of failing silently.

## 🖥️ Frontend Dashboard

Built in `app/page.tsx` as a single-page control room:

- **Metrics row** — total batch volume, reconciliation rate, unhandled exceptions, net variance
- **AI command bar** — ask the AI controller a question directly from the UI
- **Audit log table** — every transaction with a toggle between "All" and "Exceptions Only"
- **Manual re-run button** — re-triggers `/api/reconcile` on demand

## 🚀 Getting Started

### Backend (FastAPI)
```bash
pip install -r requirements.txt
export GEMINI_API_KEY=your_key_here   # required for /api/ai-query
python seed_data.py                    # (re)generate synthetic data
uvicorn main:app --reload --port 8000
```

### Frontend (Next.js)
```bash
npm install
npm run dev
```
Open [http://localhost:3000](http://localhost:3000).

> ⚠️ Note: `app/page.tsx` currently points `API_BASE` at a deployed Render URL (`https://ai-finance-control-room.onrender.com`). For local development, change this to `http://localhost:8000` or read it from an environment variable.
